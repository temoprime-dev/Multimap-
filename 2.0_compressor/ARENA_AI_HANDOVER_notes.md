## 1. Находка: KFMIRL и KFMIOP — инверсная пара

Funktionsrahmen (раздел MDBAS) прямым текстом: *"Das Kennfeld KFMIRL ist invers zum
Kennfeld KFMIOP"* — `KFMIRL` переводит (желаемый момент → нужная нагрузка `rl`), `KFMIOP` —
наоборот (нагрузка → момент, используется как потолок/проверка в координаторе момента
MDKOx). Это значит: **поднимать `KFMIRL` без согласованного подъёма `KFMIOP` рискованно** —
координатор момента может сам подрезать запрос через инверсную проверку, даже если
`LDRXN`/`KFLDIMX` формально разрешают больше буста.

В текущем `v19.xdf` `KFMIRL` уже `slot-switchable`, а `KFMIOP` всё ещё
`[stub pending: active in final build]` — то есть физически не докопирована по слотам.
**Предлагаю поднять приоритет KFMIOP до того же уровня, что и KFMIRL.**

## 2. Предлагаемый приоритет карт для докопирования по слотам

### Критично (без этого прибавка мощности не проявится или будет рассинхронизирована)
- `KFMIRL` + `KFMIOP` — **обязательно вместе**, инверсная пара (см. п.1)
- `LDRXN` / `LDRXNZK` — целевой/потолочный наддув
- `KFLDIMX` — жёсткий предел буст-дюти (сейчас тоже `stub pending`, а это hard limit)
- `KRKTE` — коэффициент впрыска (уже slot-switchable, оставить как есть; напоминание,
  что форсунки/насос на машине заменены — фактор точно нужен разный под Stage1 vs E20)

### Важно, особенно для Spirit/E20 (другая стехиометрия/ОЧ)
- `KFZW`/`KFZW2`, `KFZWOP`/`KFZWOP2`, `DZWDYN`, `DZWSPM` — уже slot-switchable, ОК
- `LAMFA`, `KFLAFWL`, `KFLAMKR`/`KFLAMKRL` — целевая лямбда, уже slot-switchable, ОК
- `FKSTT_0_A` — обогащение холодного пуска, сейчас `stub pending` — **стоит докопировать**,
  особенно под E20/E85 (в вашем же описании отмечено "Raise for E85 cold starts")

### Желательно, не критично
- `KFPED`/`KFPEDL` — уже switchable, можно оставить как есть, если не нужна разная
  отзывчивость педали между слотами
- `FBSTABGM`/`KFDLBTS`/`KFFDLBTS` — защита по EGT, сейчас `stub pending` — актуально,
  если у N55-турбины другой температурный профиль выхлопа, чем у стока
- `NMAXDVG`/`NMAXGA`/`NMAX` — лимитер оборотов, `stub pending` — только если реально
  нужен разный потолок оборотов по слотам

### Можно смело оставить общими (не копировать)
- Термостат/диагностика: `TABGBTS`, `TABGSS`, `TMOTMX`, `CWDTHM`, `THMDMMA`, `THMDMME`
  — защитные пороги, не тюнинг-параметры, разумно держать едиными на все 3 слота.

## 3. Запрос новой фичи: альтернативный триггер через кнопку A/C вместо педального ритуала

Владелец машины протестировал текущий педальный тап-ритуал "на ощупь" (без логгера) и
не смог подтвердить переключение — вероятная причина: аналоговый порог `TAP_HI`/`TAP_LO`
сложно тестировать без датлоггера (либо реально не попал в порог, либо просто не
почувствовал разницы на слух — не установлено). Просьба **добавить опциональный режим**:
детектор тапа по **физической кнопке A/C** вместо аналогового значения педали.

**Найденный подходящий сигнал:** `B_kotmsk` — "Bedingung für Klimataste ein"
(буквально: физическая кнопка A/C нажата, без всякой логики компрессора/температуры) —
адрес **`$FDA8`, бит `0x8`**. Полностью детерминированный, дискретный сигнал — ноль
проблем с порогами.

**Предлагаемая замена логики в `MM_MON`** (вместо секции сравнения педали с
`TAP_HI`/`TAP_LO`, ~`0x0AC07C–0x0AC0FE` в вашей текущей карте адресов):

```
читаем $FDA8, маска 0x8 (B_kotmsk)

если бит=0 (кнопка отпущена):
    STATE = 0
    если TAPS==0: выход (ничего не делать)
    SETTLE++
    если SETTLE == порог (CFG.SETTLE): ACTIVE = TAPS-1  (коммит!)
                                         TAPS=0, SETTLE=0
    выход

если бит=1 (кнопка нажата):
    если STATE==1 (это нажатие уже посчитано): выход
    STATE = 1
    TAPS++ (клампить на 3)
    SETTLE = 0
    выход
```

Остальная механика (индикация стрелкой N1/N2/N3, guard по `MM_NMAXOFF`, сам `CFG`-блок,
формат `ACTIVE`/`TAPS`/`SETTLE`/`STATE`) — без изменений, переиспользуется как есть.
Ритуал для владельца становится: "зажигание вкл, мотор не заведён → нажать кнопку A/C
нужное число раз (1/2/3) → подождать ~`SETTLE` циклов без нажатий → коммит", вместо
"давить газ до конкретного порога заданное число раз".

Если хочется сохранить и старый педальный режим — можно сделать выбор источника через
бит в `CFG` (например, `CFG.INPUT_SRC`: 0=педаль, 1=кнопка A/C), не удаляя старую логику.

## 4. Побочный, независимый патч (для сведения, НЕ часть multimap-системы)

Параллельно на этом же стоковом бинарнике собран отдельный, полностью независимый
минимальный патч (`switch_base_me75.bin`) — переключает только `KFZW`↔`KFZW2` через
`DAT_384905`/`FUN_09ec60`, хук в `FUN_0a1cc6` (`0x0A1CC6`), код в свободном месте
`0x0A5848+`. **Байтово не пересекается** с вашими зонами (`0x8AC000+`, `SlotPak1/2`,
`CFG`) — проверено побайтовым диффом. Упоминаю на случай, если пригодится как референс
или если понадобится сверить, что оба патча можно поставить на один файл одновременно
без конфликта (технически можно, только они будут независимо друг от друга дёргать
`DAT_384905` — при одновременной установке лучше согласовать, чей механизм "главный").
